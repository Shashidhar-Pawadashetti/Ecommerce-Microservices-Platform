  <action>
    Refactor cartStore.js so ALL writes go through one writeCart(userId, items) that serializes {"items":items,"updatedAt":new Date().toISOString()} and always issues redis.set(key, json, 'EX', CART_TTL_SECONDS). No mutation path may use SET without EX.
    Implement (idempotent, additive only where specified):
    - addItem(userId, productId, quantity): additive increment (if line exists, quantity += requested; else push {productId, quantity}); then writeCart.
    - updateQty(userId, productId, quantity): replace line quantity with absolute value (used by PATCH); writeCart. If line absent, the route layer returns LINE_NOT_IN_CART BEFORE calling this — store may treat missing as no-op or throw NotFound; choose no-op-safe but the route guards first.
    - removeItem(userId, productId): filter out the line; writeCart (idempotent — removing an absent line still writes [] and resets TTL).
    - clearCart(userId): writeCart([]) — resets TTL; idempotent.
    - readCart(userId): GET key; if null -> {items:[], updatedAt:null}; else JSON.parse -> {items, updatedAt}.
    - readTtl(userId): return await redis.ttl(key) (seconds; -1 no expire, -2 no key) so tests can assert CART-04 observable expiry.
    - readUpdatedAt(userId): return stored updatedAt or null (route uses current time when null -> Open Question 3 resolution).
    Keep the ioredis client imported from config REDIS_URL. Do not change function names used by 04-02 (updateQty/removeItem/clearCart must exist).
  </action>
