## Pattern Assignments

### `scripts/smoke-auth.sh` (utility, request-response)

**Analog:** `scripts/check-contracts.sh` — copy its skeleton wholesale.

**Script preamble & failure accumulation** (`scripts/check-contracts.sh` lines 26–35):
```bash
set -euo pipefail

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
cd "$ROOT"

FAIL=0
fail() { echo "FAIL: $1"; FAIL=1; }
skip() { echo "SKIP: $1"; }

echo "== check-contracts: mechanical contract drift gate =="
```

**Assertion helper style** (lines 78–85 — local function + grep-style check, ok/fail branches):
```bash
assert_pin() {
    local label="$1" pattern="$2"
    if grep -qiE "$pattern" "$VERSIONS_FILE"; then
      echo "   ok: $label"
    else
      fail "manifest missing pin: $label"
    fi
}
```

**Adaptation notes for smoke-auth.sh:**
- Same shebang, `set -euo pipefail`, ROOT resolution, boxed header comment.
- Keep the accumulate-and-exit-non-zero habit OR fail-fast per assertion (research's jq-free snippet uses `[ … ] || { echo "FAIL …"; exit 1; }` — either matches house style; pick one).
- Status-code assertions via pure curl (no jq on host) — body from RESEARCH.md Code Examples (lines 552–569).
- **LF endings mandatory**: `.gitattributes` line 8 (`* text=auto eol=lf`) is repo law; verify with `git ls-files --eol` showing `i/lf` after commit (same Stage-3 rule check-contracts enforces).

### Wire-shape files: DTOs, `ApiError`, `GlobalExceptionHandler`, `RestAuthenticationEntryPoint`

**Analog (contract-source):** `docs/api-contracts/_shared.yaml` — copy example strings EXACTLY; they are asserted by tests/smoke later.

**Unified error envelope schema** (`_shared.yaml` lines 69–91):
```yaml
schemas:
  Error:
    type: object
    description: >-
      Unified error envelope returned by every service on failure. Clients
      correlate and branch on the machine-readable code; the message is for
      humans only.
    required: [code, message]
```

**Exact response bodies to emit** (`_shared.yaml` lines 99–131):
```yaml
ValidationError → 400: {code: VALIDATION_FAILED,   message: "Request validation failed. Check field formats and limits."}
Unauthorized    → 401: {code: UNAUTHORIZED,        message: "Authentication required or credentials invalid."}
Conflict        → 409: {code: DUPLICATE_EMAIL,     message: "An account with this email already exists."}
```

Message law (lines 84–87): *"MUST NOT leak internals: no hostnames, stack traces, or driver/database errors"* — log internals server-side only (research Pattern 4 shows `log.warn` before returning sanitized envelope).

**DTO shapes** (`auth-service.openapi.yaml` lines 154–198):
- `EmailPassword`: `{email (format email), password (minLength 8)}`
- `User`: required `[id, email, roles, createdAt]` — id is **string** on the wire (interop Rule 3), roles string array, createdAt `date-time`
- `AccessTokenPair`: required `[accessToken, user]` where user reuses the User shape (login response carries the SAME user object as `/me` — spec lines 92–93)

**Timestamp serialization guard** (`docs/json-interop.md` Rule 1, Java row line 31):
> *"Default serialization of `java.time` types without configuration produces arrays ([2026,8,24,…]) or ISO strings without millis — drifts from the canonical form. Guard: Register JavaTimeModule, set WRITE_DATES_AS_TIMESTAMPS=false, use millisecond formatting."*

Canonical form (line 21): `2026-08-24T12:00:00.123Z` — exactly 3 fractional digits + `Z`. Apply `@JsonFormat(shape = STRING, pattern = "yyyy-MM-dd'T'HH:mm:ss.SSS'Z'", timezone = "UTC")` on `createdAt` (research Pitfall 3) and add an integration-test regex assertion.

**JWT claims the token must carry** (`json-interop.md` lines 103–111 — single canonical home):
```
sub = userId (string) · email · roles=["customer"] · iss="ecommerce-auth"
aud="ecommerce-api" · iat/exp epoch seconds · TTL 3600s · ±60s skew at verify
```
Algorithm pinned by name both sides (lines 113–116); secret rules items 1–5 (lines 128–136) drive `JwtSecretAssertion` (log length, never content).
