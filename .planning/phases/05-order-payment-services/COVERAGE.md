# Phase 5 — API Coverage Decision Matrix (Order + Payment Services)

> Generated by the `api-coverage` contribution (plan:pre). This phase integrates
> external surfaces; each is enumerated below with an INTEGRATE / OPT-OUT decision
> and the reason. No external surface is silently omitted.

## Surfaces in scope

| # | Surface | Direction | Decision | Reason |
|---|---------|-----------|----------|--------|
| 1 | **cart-service HTTP** (`GET /cart/{userId}`, `DELETE /cart`) | order-service → cart-service (caller) | **INTEGRATE** | Mandatory: checkout snapshots the priced cart (ORDR-01) and clears it after success (ORDR-06). Contract frozen in `services/cart-service/src/routes/internal.js` + `routes/cart.js` + `totals.js`. order-service uses a Spring `WebClient`, forwards the caller's `Authorization` header verbatim, and derives `sub` from the token — it never synthesizes a userId (RESEARCH Pattern 3). |
| 2 | **Apache Kafka `apache/kafka:4.2.1` (KRaft)** | order-service → `order.created` (producer); payment-service → `order.created` (consumer) + `payment.completed` (producer); order-service → `payment.completed` (consumer) | **INTEGRATE** | The saga IS the phase. Topics `order.created` / `payment.completed` are provisioned by a `kafka-init` init container (3 partitions, RF=1, key=`orderId`); `auto.create.topics.enable=false` per `docs/kafka-topics.md`. |
| 3 | **Redis `redis:8-alpine` (existing)** | payment-service → `SETNX` dedup key `payment:authorized:{orderId}` | **INTEGRATE** | Dedup store that survives container restart; prevents double mock-authorization on redelivery (ORDR-03 / ORDR-08). Reuses the already-running Redis — no new datastore. |
| 4 | **PostgreSQL `postgres:18` (existing)** | order-service → `orders` DB + `idempotency_keys` table (Flyway V1) | **INTEGRATE** | System of record for orders and the HTTP-replay idempotency store (ORDR-05). New `orders` database added via an idempotent init container (RESEARCH Pitfall 4). |
| 5 | **kafka-ui `provectuslabs/kafka-ui:latest`** | read-only observability | **INTEGRATE (dev-only)** | Makes the ORDR-08 crash/redelivery visible (topic content, consumer-group lag). Not runtime-critical; excluded from the Phase 7 gateway route table. |

## Out of scope / explicitly opted out

- **No real payment processor (Stripe/PayPal).** Mock authorization driven by `PAYMENT_MODE` is a deliberate v1 exclusion (REQUIREMENTS.md Out of Scope).
- **No Schema Registry / Avro.** Two flat message shapes are the registry (`docs/kafka-topics.md`).
- **No `NewTopic` Spring beans** for topic creation — would silently auto-create and violate the contract's fixed partition/RF stance. Init container only.

## Package legitimacy

`aiokafka`, `redis` (payment-service) and `spring-kafka` / `spring-kafka-test` (order-service) were vetted in `05-RESEARCH.md` Package Legitimacy Audit. The Python packages carry a `SUS` verdict on a telemetry-only signal; all versions are the authoritative pins from `docs/versions.md`. No `checkpoint:human-verify` gate is added beyond the existing `docs/versions.md` governance (per research guidance).

## Conclusion

Full external-surface coverage. Every consumer is idempotent by construction (terminal-state guard + Redis `SETNX` + unique `idempotency_keys.key`), satisfying the at-least-once delivery contract.

## Verification status (Plan 05-01)

Both services are verified by automated suites (no Docker Compose required for the unit/integration tier):

- **order-service** — `OrderSagaIntegrationTests` (EmbeddedKafka + Testcontainers PostgreSQL):
  - publishes `order.created` to the broker on checkout;
  - `payment.completed` (APPROVED) drives the order to `PAID`; (DECLINED) to `PAYMENT_FAILED`;
  - `Idempotency-Key` replay returns the **same** order (HTTP 200);
  - a non-owner `GET /orders/{id}` returns **404** (no ownership leak). ✅ green
- **payment-service** — `tests/test_saga.py` (real RedisContainer + fake producer):
  - `always_success` → `APPROVED` with `reason` omitted (interop Rule 4);
  - `always_fail` → `DECLINED` with `reason` present;
  - redelivered `order.created` → `SETNX` dedup → exactly **one** `payment.completed` produced. ✅ green
- **End-to-end smoke** — `scripts/phase5-tracer-smoke.sh` (full `docker compose` stack):
  signup → cart → checkout → `PAID`.
- **Crash recovery** — `scripts/phase5-kill-test.sh` (ORDR-08): kill `payment-service`
  before it consumes `order.created`, restart, assert the order still reaches `PAID`.
